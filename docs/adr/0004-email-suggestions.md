# ADR-0004: Gmail MCP application tracking and automatic Moves

Accepted: 2026-11-15. Issue #167 supersedes #140's confirmed suggestions and ADR-0003's IMAP connection. It also amends ADR-0001/0002: a clear emailed confirmation may create a Manual Source Job and an automatic Applied Move for an application made outside Joule.

Run MIT-licensed taylorwilsdon/google_workspace_mcp at commit `43b662a938ef002626ac269451c469b91979bd9a` inside the Docker container, in an isolated Python environment. A small launcher selects Gmail only, read-only, single-user stdio. It removes upstream's default OIDC scopes, checks the actual access-token grant with Google at every startup, verifies the mailbox identity, and refuses anything other than exactly `gmail.readonly`. OAuth uses the operator's own Cloud desktop client and an offline grant; interactive setup is separate from unattended operation. Upstream refresh and pagination are reused. No IMAP fallback, passwords, Connect/Manage dialog or PUT/DELETE connection contract remains; startup deletes legacy email.json and drops retired suggestion/cursor tables without replaying their contents.

Every 15 minutes (including startup), a dedicated ephemeral Codex run receives `search_gmail_messages`, `get_gmail_message_content` and a local read-only `lookup_jobs` tool, with other tools disabled. The lookup returns at most 20 candidates plus an explicit truncation flag, includes closed and non-Applied Jobs, and keeps the full Job catalog out of the prompt. Its SQLite connection opens in read-only mode. Python runs in isolated mode and the launcher removes its own package directory from import search paths to prevent shadowing upstream modules. It is separate from the scoring session. The agent decides matches, intent, discovery and uncertainty; email is untrusted data, never instructions. Search begins 14 days back on first use, then overlaps the last successful checkpoint by one day. The attempt time and a frozen window end are recorded before I/O. The launcher exposes a zero-argument search tool pinned to the supplied query/page token, caches that page in memory, and forces a page size of ten, so the model cannot widen or paginate the search within a run. Each run processes that one page, with a separate 900-second mail deadline rather than scoring’s 300 seconds. A complete page saves the server’s opaque next-page token; only the final complete page advances the window checkpoint. A retry keeps the same window and page token. Joule computes the actual overlapping bound and Gmail epoch-second query. Partial results may apply and deduplicate on retry. Retained text is truncated before validation; there is no 100-result array cap. Incomplete or queued pages show checking/processing backlog; provider failures show unavailable, without logging provider text. Provider schema-limit enforcement is not relied upon.

Joule validates schema and known Job IDs. Under one SQLite write transaction it rejects results for Jobs removed or re-applied, later manual Moves, or messages predating the current application. Certain forward Stage, rejection and timezone-aware Next date results append automatic Moves using the existing history function. Under the operator’s adopted P1 ruling, a reply dated later than a current automatic No reply closure may reopen the same application and move forward or set a Next date. A rejection replaces No reply with Rejected. Manual No reply and other closures remain protected. Under P2, acceptance mail is capped at Offer and always leaves a review flag; it never sets Accepted automatically or downgrades a manually Accepted Job. Stable account/Gmail-message identities deduplicate results and discovery. Multiple messages in one run can act on the same application; earlier automatic Moves in that transaction do not invalidate later results. A clear external confirmation can create a Manual Source Job with title/company and Gmail link, then an automatic Applied Move dated to the confirmation. It cannot resurrect a previously discovered Job unmarked by the operator. Discovery checks stored URL aliases through job_urls.resolve and the existing normalized company/title vocabulary across all Primary Jobs before inserting; under the adopted P3 ruling, a unique match reuses that existing Job and marks it Applied with an automatic entry dated to the confirmation. Its Source, content, score and other metadata remain intact. Already-Applied matches do not reset history. Multiple/conflicting matches or candidates changed by the operator during the run are review flags, never duplicate insertions or automatic overwrites. An already-created discovery in the same transaction participates in this check. Normal Source Scans do not enqueue Manual Jobs; explicit rescoring can still select one.

Uncertain or ambiguous matched messages persist as flags for candidate current Pipeline Jobs and never move them. Pipeline's From Gmail rail links to each candidate for manual review and allows dismissal. Results suppressed by closed/backward guards or producing unchanged dates are also flags, never recorded as applied. Acceptance flags require the operator’s manual Accepted decision even when the mail itself is certain. Other certain results have no confirmation queue. Flags and card counts belong to the current application; historical records remain private after unmark/re-apply.

Retain sender, subject, at most one 140-character line, date, Gmail ID, matched Job/application and disposition only. Bodies, attachments and unmatched messages are not stored by Joule. The read tool's upstream full-message export path is explicitly disabled, and attachment/download tools are not exposed. MCP stdio is consumed in memory; Codex runs ephemerally with history disabled and logs/SQLite in the temporary run directory, removed on completion, failure or cancellation. Mail stderr is discarded without retaining diagnostic text. OAuth credentials alone persist privately under gmail/credentials. There is no former 16 KiB IMAP wire-fetch guarantee: Gmail tools may read a full message in memory. This retention policy does not prevent model-provider processing; the operator must use suitable provider data settings.

Operator rulings adopted 2026-11-15: “go with your picks for now for 1-3” — P1 reopens and moves automatic No reply closures on later replies (or re-closes as Rejected); P2 stops acceptance mail at Offer and flags it; P3 links confirmations to unique existing Jobs and marks them Applied. These supersede the provisional flag-only handling of No reply replies and existing non-Applied discovery matches, and the earlier automatic Accepted permission. The validation snapshot includes existing Job states as well as Move IDs to protect operator changes during discovery.
