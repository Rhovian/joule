# ADR-0004: Read-only mail and confirmed Pipeline suggestions

Accepted: 2026-11-12. Issue #140 extends ADR-0003's connection-only boundary.

Use the existing TLS IMAP session and structured AI transport. Account/folder cursors in SQLite track UIDVALIDITY, last UID and last check attempt. A server task evaluates the stored interval every minute, including startup; null means a completed Scan signals the background loop, after Scan cleanup and alerts; cancelled Scans do not. Checks never hold Scan busy. Attempt time is persisted before network I/O so failures respect the interval. Invalid classifier output stores only a failed dedupe key and continues. Transient AI errors retain the cursor behind the first such message for retry at the next interval, while later messages can still produce suggestions and deduplicate on retry; transport failure keeps the UID cursor for the next due attempt. Authentication failure reusing saved credentials pauses checks until a successful connection save clears expiration; transport errors do not expire credentials. Unexpected errors are logged without remote exception text and do not end the loop.

Only unique deterministic matches to current Pipeline Jobs are retained. Match sender domains against company names and stored Job/application hosts; shared ATS domains require the company name in subject/quote. Source-labelled link hosts derive from the supported Source vocabulary and stored Job links, so board newsletters cannot match their own postings; system-provider subdomains are excluded; employer no-reply addresses remain eligible. Multiple matching Jobs are ambiguous and discarded. This deliberately favours missing suggestions over attaching mail to the wrong Job.

Fetch at most the first 16 KiB of each new message using BODY.PEEK, parse with stdlib email, and pass at most 4,000 body characters to one structured classifier. Bodies/attachments and unmatched messages are never persisted or logged. Retain sender name/address, subject, first non-quoted body line (140 chars), date, Message-ID, folder/UID, matched Job/current application, proposal and resolution. Missing Message-ID uses a folder/UIDVALIDITY/UID identity. For classifier none/backward/failed outcomes, retain only account, Message-ID, Job and outcome in a separate dedupe table, with no sender, subject, quote or application data and no card count. HTML head/style/script/blockquote blocks are discarded before extracting text. The UI escapes all mail text.

Confirm alone appends a manual Move naming the sender and subject, in the same transaction resolving the suggestion. A stale application/Move returns 409 rather than overwriting later operator work. Exclude preserves the account/Message-ID/Job record and suppresses redelivery, including after UIDVALIDITY changes. Ignore keeps metadata but removes the pending suggestion. Reconnection preserves history/exclusions; changing host/user retains the old account’s rows until Disconnect, but the new account cannot see them. Disconnect purges all stored suggestions, exclusions, dedupe keys and check cursors along with credentials. In-flight checks discard results if the saved connection changed or was disconnected. Card email counts belong to the current application only. Stage suggestions only move on; date/rejection suggestions retain the current Stage. No email is sent, marked Seen, deleted or otherwise changed.
