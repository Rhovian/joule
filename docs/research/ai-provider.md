# Pluggable AI providers for joule

**Recommend a thin in-house async interface over the official Python SDKs:** Anthropic for Claude, OpenAI for OpenAI, and that same OpenAI client against local Ollama. Native structured output is available without a provider framework; Claude must use its native API because its OpenAI compatibility layer ignores `response_format`. [Claude](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [Ollama](https://docs.ollama.com/api/openai-compatibility), [Claude compatibility limits](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk).
Keep scoring/Draft schemas and a SQLite usage ledger in joule; return validated data plus normalized usage and an estimated USD cost. This is a design recommendation based on the narrow three-provider question and job-ops' existing strategy boundary. [Ticket #5](https://github.com/Rhovian/joule/issues/5), `/Users/j/code/job-ops/orchestrator/src/server/services/llm/types.ts:88`.
**Runner-up: `pydantic-ai-slim[openai,anthropic]`** if automatic validation retries and normalized model metadata become substantial work; LiteLLM offers stronger ready-made cost/provider breadth at a larger dependency footprint. [Pydantic output](https://ai.pydantic.dev/output/), [Pydantic package metadata](https://pypi.org/pypi/pydantic-ai-slim/2.54.0/json), [LiteLLM cost](https://docs.litellm.ai/docs/completion/token_usage), [LiteLLM package metadata](https://pypi.org/pypi/litellm/1.104.1/json).
Do not choose a single OpenAI-compatible endpoint abstraction for all three: Claude explicitly describes that compatibility layer as primarily for evaluation rather than a long-term production solution. [Anthropic's guidance](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk).

## Recommended boundary and accounting

The following is proposed design, not existing joule behavior. It follows job-ops' request/strategy separation while adding usage data absent from its public success result. `/Users/j/code/job-ops/orchestrator/src/server/services/llm/types.ts:45`, `/Users/j/code/job-ops/orchestrator/src/server/services/llm/types.ts:62`, `/Users/j/code/job-ops/orchestrator/src/server/services/llm/types.ts:88`.

- Define one async `generate(request, output_type) -> GenerationResult[T]` interface. Request contains provider/model configuration, system text, input, timeout and output-token limit; result contains validated data, actual model, request ID if available, finish status and usage. Scoring and Draft services own their Pydantic schemas and prompts. Keep provider mechanics behind adapters. Basis: official structured parsing helpers and job-ops' request boundary. [Claude helper](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [OpenAI helper](https://developers.openai.com/api/docs/guides/structured-outputs), `/Users/j/code/job-ops/orchestrator/src/server/services/llm/types.ts:45`.
- Use Claude's native SDK, OpenAI's native SDK, and OpenAI Chat Completions against local Ollama. Require native schema support for the configured scoring model; surface unsupported capabilities rather than silently accepting unvalidated text. All three routes have documented structured output, but support is model/API dependent. [Claude](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [local Ollama](https://docs.ollama.com/capabilities/structured-outputs).
- Record an attempt before output validation, associating it with the Job and Scan or requested Draft. Preserve provider-specific usage fields alongside normalized input/output/cache counts, estimate USD using a versioned rate snapshot, and store `unknown` when usage/rates are unavailable. This is an accounting recommendation because Anthropic prices cache reads/writes separately and Ollama exposes token counts/durations rather than a dollar charge. [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing), [Ollama usage fields](https://docs.ollama.com/api/chat). For self-hosted Ollama, label API spend as zero by explicit local policy; hardware/electricity cost is outside that estimate.
- Prefer a small configured rate table for initially supported model IDs; adopt standalone `genai-prices` if keeping rates current becomes burdensome. It supports historic and tiered pricing, but still requires a model/provider match and is not the provider's invoice. [Pricing helper](https://github.com/pydantic/genai-prices). Persist usage even when cost lookup fails; pricing must not discard a successful scoring result or Draft. This is proposed failure policy, supported by the separation of usage and pricing APIs. [Pydantic usage](https://ai.pydantic.dev/api/usage/), [cost method](https://ai.pydantic.dev/api/messages/).
- Set explicit retry/timeout budgets and keep transport retries separate from a bounded validation-repair attempt. OpenAI and Anthropic SDKs each retry selected transient errors twice by default; wrapping them in another retry loop can multiply calls. [OpenAI retries](https://github.com/openai/openai-python#retries), [Anthropic retries](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/python#retries). Keep Profile/prompt contents out of the usage ledger; Profile is private material by definition. `/Users/j/code/joule/GLOSSARY.md:19`.

job-ops already treats Anthropic as a native `/v1/messages` strategy and Ollama as `/v1/chat/completions`, and has separate retry/capability policies. Reuse those architectural lessons, not its TypeScript implementation or broad provider set. `/Users/j/code/job-ops/orchestrator/src/server/services/llm/providers/anthropic.ts:93`, `/Users/j/code/job-ops/orchestrator/src/server/services/llm/providers/ollama.ts:8`, `/Users/j/code/job-ops/orchestrator/src/server/services/llm/policies/retry-policy.ts:7`, `/Users/j/code/job-ops/orchestrator/src/server/services/llm/policies/capability-fallback.ts:3`.

## Open risks and what would verify them

1. **No live provider verification.** Model quality, semantic scoring accuracy, latency and schema compatibility with joule's eventual schemas are unverified. Before implementation sign-off, run the same small scoring/Draft fixture set through pinned Claude, OpenAI and local Ollama models; include bounded numeric fields, nested objects, refusals and truncation. Schema conformance is not a quality guarantee, and OpenAI documents refusal/incomplete-response paths. [OpenAI structured-output guide](https://developers.openai.com/api/docs/guides/structured-outputs).
2. **Schema subsets and API evolution.** Claude's SDK simplifies unsupported constraints and validates against the original schema afterward. LiteLLM's Anthropic page and current transformation source still use older `output_format` terminology, while native Claude docs specify `output_config.format`; Claude documents a transition accepting the old field. This is a version-compatibility risk, not evidence that LiteLLM is broken. Verify actual requests using the pinned installed release before selecting it. [Native schema transformation/migration](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [LiteLLM docs](https://docs.litellm.ai/docs/providers/anthropic), [transformation source](https://github.com/BerriAI/litellm/blob/main/litellm/llms/anthropic/chat/transformation.py).
3. **Cost estimates are incomplete when usage is missing.** A timeout after generation may leave no response usage to record; an exact invoice-reconciled total is unverified. Preserve failed/unknown attempts, label totals as estimates and compare with provider billing when needed. Caching and pricing tiers make simple aggregate input/output multiplication insufficient. [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing), [genai-prices capabilities](https://github.com/pydantic/genai-prices).
4. **Local Ollama is a deployment assumption.** Ollama Cloud explicitly does not support structured output; this recommendation targets a local Ollama server. The server's location, model storage and hardware are unspecified in the brief. Verify the configured base URL from inside joule's container and run a schema call; do not assume the container's `localhost` reaches a host-side server. [Cloud limitation](https://docs.ollama.com/capabilities/structured-outputs), [Ollama local endpoint](https://docs.ollama.com/api/openai-compatibility).
5. **Full dependency and maintenance measurements remain unverified.** No installation, gate, import benchmark, Docker build or Python-version resolution was run. Verify a lockfile on joule's chosen Python version and measure final image size if footprint becomes decisive. The recommendation should be revisited if more providers or substantial repair logic are needed; slim's output validation/retry support then becomes more valuable. [Published slim requirements](https://pypi.org/pypi/pydantic-ai-slim/2.54.0/json), [Pydantic output support](https://ai.pydantic.dev/output/).
