# Job-board Sources for joule

Recommend **Hacker News Who’s Hiring, We Work Remotely RSS, and RemoteOK JSON** as the first Sources: each has a first-party read interface; WWR and RemoteOK require attribution links. [HN API](https://github.com/HackerNews/API), [WWR RSS policy](https://weworkremotely.com/remote-job-rss-feed), [RemoteOK API terms](https://remoteok.com/api).
Add **web3.career optionally after obtaining a private API token**; its API supports JSON/RSS but limits each query to 100 recent Jobs without offset/cursor pagination. [Official overview](https://docs.bondex.app/api-reference/web3-career-jobs-api/api-overview.md).
Use **JobSpy → Indeed as an opt-in coverage expansion**, with a pinned version and visible Scan errors; defer LinkedIn/Glassdoor and exclude Google Jobs initially because of blocking, partial-result behavior and unavailable Google coverage. [JobSpy notes](https://github.com/speedyapply/JobSpy#notes), [LinkedIn implementation](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/linkedin/__init__.py#L69).
These are engineering recommendations from the evidence below, not claims of guaranteed availability; one successful read does not establish a sustained request quota.

## JobSpy: maintained scraper library, not a contracted job-data API

**Maintenance.** GitHub reports `archived=false`; the inspected head was `655ec04663b798742704f1038262b631cd1988f2`, committed 2026-10-07. Same-day commits fix Glassdoor paging/descriptions, ZipRecruiter, Bayt, Naukri and BDJobs. This demonstrates current maintenance and recent implementation churn, not reliability of every Source. [Commit history](https://github.com/speedyapply/JobSpy/commits/main/), [inspected commit](https://github.com/speedyapply/JobSpy/commit/655ec04663b798742704f1038262b631cd1988f2). Command evidence: `gh api repos/speedyapply/JobSpy --jq '{archived,pushed_at}'` printed `false` and `2026-10-07T07:01:39Z`; `gh api 'repos/speedyapply/JobSpy/commits?per_page=5'` returned those fixes.

PyPI currently publishes **python-jobspy 1.2.0**, uploaded 2026-10-02, requiring Python >=3.10. This is older than the inspected GitHub head: do not assume unreleased fixes are in the package. [PyPI metadata](https://pypi.org/pypi/python-jobspy/json). Command evidence: Python `urllib.request.urlopen` of that URL printed version `1.2.0`, `requires_python >=3.10`, wheel upload `2026-10-02T05:28:16.606228Z`.

**Access and coverage.** `scrape_jobs()` dispatches to LinkedIn, Indeed, ZipRecruiter, Glassdoor, Google, Bayt, Naukri and BDJobs, returning a pandas DataFrame. None of the four smaller Sources in this brief is in that mapping. [Dispatcher](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/__init__.py#L31). Indeed uses an internal GraphQL endpoint; LinkedIn parses guest-search HTML; Glassdoor queries internal GraphQL. Calling these endpoints through a scraper does not demonstrate an officially supported integration agreement. [Indeed](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/indeed/__init__.py#L33), [LinkedIn](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/linkedin/__init__.py#L74), [Glassdoor](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/glassdoor/__init__.py#L58).

Upstream describes LinkedIn as global, ZipRecruiter as US/Canada, Indeed/Glassdoor as country-dependent, Bayt as broad regional coverage, BDJobs as Bangladesh, and Naukri as India. Google is explicitly “currently unavailable.” [Coverage and FAQ](https://github.com/speedyapply/JobSpy#supported-countries-for-job-searching).

**Fields.** The model includes ID, title, company, Source/direct Job URLs, location, description, company URLs, Job types, compensation interval/min/max/currency, posted date, emails and remote flag. Optional extras include seniority/function, company industry/address/headcount/revenue/description/logo, skills, experience, company ratings/reviews, vacancies and work-from-home type. Availability varies by Source; the schema permits many nulls. [JobPost and compensation models](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/model.py#L219).

**Limits and failures.** Upstream estimates roughly 1,000 Jobs/search, LinkedIn throttling near page ten/IP and Glassdoor throttling after roughly 30 requests/IP. It describes Indeed as having no current rate limiting, but also warns that Sources aggressively block and may return 429; treat these as maintainer observations, not quotas or permission guarantees. [Notes/FAQ](https://github.com/speedyapply/JobSpy#notes). Current LinkedIn code waits 3–7 seconds between pages and ignores `is_remote`/`job_type` filters. Non-200 or suspicious empty pages stop iteration and return accumulated Jobs, so an incomplete Scan can look successful. [LinkedIn code](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/linkedin/__init__.py#L39). Glassdoor detail fetching is now batched in groups of 25, contradicting the README’s generic one-request-per-Job description for this Source. [Detail fetching](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/glassdoor/__init__.py#L238).

**Local job-ops precedent.** Its manifest exposes only Indeed, LinkedIn and Glassdoor, and requirements leave JobSpy unpinned. It passes the deprecated `linkedin_fetch_description` argument, defaults to 200 results and catches raised exceptions per Source. That exception handling cannot alone detect the upstream partial-result paths above. ## Hacker News Who’s Hiring

**Access.** Use the public Firebase JSON API, not page scraping. Read `/v0/user/whoishiring.json`, inspect submitted story IDs for the exact hiring-thread title, read its `kids`, then fetch each direct child with `/v0/item/<id>.json`. Do not substitute the separate HN job-story collection or the “Who wants to be hired?” thread. The current hiring thread is story **49922569**, whereas 49922568 is the candidate thread. [User API](https://hacker-news.firebaseio.com/v0/user/whoishiring.json), [hiring story](https://hacker-news.firebaseio.com/v0/item/49922569.json), [candidate story](https://hacker-news.firebaseio.com/v0/item/49922568.json).

**Fields.** Hiring Jobs arrive as comments: `id`, `by`, Unix `time`, HTML `text`, `parent`, `type`, optional `kids`, `deleted`/`dead`. Company, role, salary, geography, remote restrictions and application links are prose, not structured Job fields. One company comment can describe several roles. [API schema](https://github.com/HackerNews/API#items), [live company comment](https://hacker-news.firebaseio.com/v0/item/49998400.json).

**Limits/blocks.** Official docs state no current rate limit. There is no bulk expanded-thread endpoint in the documented v0 interface; child IDs require individual reads. The thread asks for employer-only, actively hiring company comments and explicit remote restrictions, but this does not guarantee completeness or continued availability. [API design](https://github.com/HackerNews/API#design), [thread instructions](https://news.ycombinator.com/item?id=49922569). Live Python reads returned HTTP 200; the story had 283 direct child IDs at inspection. Recommendation: cache by comment ID and retain raw text; recheck edits/deletions on a modest schedule.

## We Work Remotely

**Access.** Public all-Jobs RSS at `https://weworkremotely.com/remote-jobs.rss`, plus category RSS URLs. WWR explicitly permits anyone to use the feed with links attributed back to WWR. [Published feeds/policy](https://weworkremotely.com/remote-job-rss-feed).

**Fields, verified live.** RSS items contained `title` (company and role combined), `link`, `guid`, `pubDate`, HTML `description`, `region`, `country`, `state`, `skills`, `category`, `type`, `expires_at`, and media content. No separate structured company, salary or employer apply URL appeared in the inspected first item. The response had 89 Jobs and channel `ttl=60` (RSS minutes, not seconds). [First-party RSS](https://weworkremotely.com/remote-jobs.rss). Evidence: Python `urllib.request` with `User-Agent: Mozilla/5.0`, parsed by `xml.etree.ElementTree`, printed HTTP 200, 89 items and those tags. Counts and optional-field presence are snapshots, not a retention contract.

**Limits/blocks.** No numeric RSS quota or archive/pagination guarantee was found on the feed page. The separate token-authenticated JSON API documents posting, updating and reading individual Jobs; it does not establish public bulk read access. It states 1,000 authenticated requests/day, but its 429 example says monthly quota: that inconsistency concerns the API, not RSS. [API docs](https://weworkremotely.com/api#rate-limiting). Python’s default user agent received 403 for RSS; the browser user agent received 200 here. Cause is unverified. Recommendation: hourly RSS Scans, local filtering and WWR links, without detail-page scraping initially.

## RemoteOK

**Access and fields.** The official site links to its public JSON feed/API. No credential was needed for a successful read of `/api`. The array’s first object is metadata (`last_updated`, `legal`), followed by Jobs with `id`, `slug`, `epoch`, `date`, `company`, `company_logo`, `position`, `tags`, HTML `description`, `location`, `apply_url`, `original`, `verified`, `salary_min`, `salary_max`, `logo`, `url`. [Official feed link](https://remoteok.com/), [API](https://remoteok.com/api). Live Python read with `User-Agent: Mozilla/5.0` returned HTTP 200 and 100 array entries: one metadata object plus 99 Jobs. Do not import metadata as a Job or assume this is the entire inventory.

**Limits/blocks.** Embedded terms require follow links to RemoteOK Job URLs and naming Remote OK as the Source; missing attribution can suspend access. Logo use requires written permission. No numeric request quota, supported pagination or salary currency/unit contract was verified from the response. Salary zero appears in returned Jobs; preserve it as unknown rather than interpreting it as paid-zero. [API response/terms](https://remoteok.com/api). The default Python user agent returned 403; a browser user agent returned 200. Recommendation: hourly full-feed Scans with local filtering and deduplication by Source ID; keep Source `url` for attribution alongside `apply_url`.

## web3.career

**Access and limits.** Its official site advertises free access and links to Bondex documentation. Use token-authenticated `GET /api/v1` JSON or `/api/v1.xml` RSS. Filters are one exact tag, country slug, `remote=true`, `limit` 1–100, and `show_description`. No offset/cursor exists; these return recent Jobs, not an accessible archive. Invalid tag/country may silently return 200 with no Jobs. Rate limiting yields 429; no numeric quota was found. [Landing page](https://web3.career/web3-jobs-api), [endpoint specification](https://docs.bondex.app/api-reference/openapi-documentation/web3.career-jobs-api.md), [silent failures](https://docs.bondex.app/api-reference/openapi-documentation/silent-filter-failures.md).

**Fields and uncertainty.** Official schema documents `id`, `title`, `company`, `location`, `remote`, HTML `description`, `tags`, `apply_url`, `url`, optional `salary`, `postedAt`, with no required fields and extra fields allowed. JSON mixes metadata strings and a nested Jobs array. [Models](https://docs.bondex.app/api-reference/openapi-documentation/models.md). A first-party API response surfaced in web search instead used `is_remote`, `date`, `date_epoch`, country/city, explicit salary bounds/currency/unit and estimated salary fields. This is a schema discrepancy, not a verified stable contract. An authenticated fresh response with the owner’s token must settle the actual mapping; do not treat estimated salaries as employer-stated pay. [API endpoint](https://web3.career/api/v1). No token was available for a fresh authenticated probe; the unauthenticated request returned 403 in this environment.

**Conditions.** Preserve the original `apply_url`, use follow links and attribute web3.career. Tokens must remain private and out of client code/logged URLs; missing link attribution can suspend access. [Official terms](https://docs.bondex.app/api-reference/web3-career-jobs-api/api-overview.md#terms-of-use). Recommendation: optional Source after a token-backed schema check, explicit `limit=100` and descriptions enabled, with restrained scheduled Scans and 429 backoff.

## Open risks and first-set decision

- **Recommended first set:** HN + WWR + RemoteOK. They supply raw descriptions through published first-party interfaces; the cost is HN prose extraction and WWR/RemoteOK attribution. This recommendation follows their documented interfaces and the live field observations above. Keep web3.career optional for Web3 interest and token availability; enable Indeed through JobSpy only when broader coverage is needed.
- **Deployment access remains unverified.** The observed user-agent-sensitive 403/200 behavior is evidence of request sensitivity, not proof of a particular anti-bot product or permission to bypass blocks. Verify one normal read from the actual Docker host for each enabled Source before relying on scheduling. Evidence: the live WWR/RemoteOK probes described above.
- **Retention is incomplete/uncertain.** WWR and RemoteOK sample sizes do not establish backfill depth or expiry semantics; web3.career explicitly lacks pagination. Persist fetched Jobs locally rather than promising complete historic coverage. [WWR RSS](https://weworkremotely.com/remote-jobs.rss), [RemoteOK API](https://remoteok.com/api), [web3 endpoint specification](https://docs.bondex.app/api-reference/openapi-documentation/web3.career-jobs-api.md).
- **Extraction needs provenance.** HN remote/salary/role fields are inferred from text; JobSpy models allow missing fields; web3 documentation and observed response names disagree. Preserve raw payloads and distinguish inferred/estimated values. [HN schema](https://github.com/HackerNews/API#items), [JobSpy model](https://github.com/speedyapply/JobSpy/blob/655ec04663b798742704f1038262b631cd1988f2/jobspy/model.py#L232), [web3 models](https://docs.bondex.app/api-reference/openapi-documentation/models.md).
- **No sustained quotas were measured.** HN’s no-limit statement is documented; JobSpy thresholds are approximate; WWR’s authenticated API quota must not be applied to RSS; RemoteOK/web3 numeric quotas remain unverified. Use conservative schedules, caching and bounded retries, and report failed/partial Scans visibly. [HN docs](https://github.com/HackerNews/API#uri-and-versioning), [JobSpy notes](https://github.com/speedyapply/JobSpy#notes), [WWR API](https://weworkremotely.com/api), [web3 guidance](https://docs.bondex.app/api-reference/web3-career-jobs-api/api-best-practices.md).
