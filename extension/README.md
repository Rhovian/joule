# Joule Fill

Load this directory unpacked from Chrome's `chrome://extensions` with Developer mode enabled. Open extension Options, enter the joule origin (for example `http://localhost:8000` or the Tailscale Serve HTTPS origin), and click **Save and Test**. For a server, set joule's `UPWORK_REDIRECT_URI` to allow the tailnet hostname.

Open a Greenhouse, Lever or Ashby form and click the extension toolbar action to open the side panel. It detects the Job from the current page URL; check the displayed title/company and click **Fill**. Detection refreshes on tab switches and navigation. Reload a form that was already open when the extension was installed. Review the values and complete the remaining fields yourself. Job state stays manual.

Detection compares stored Job links, Duplicate links and saved destination URLs, ignoring fragments and common tracking parameters. Lever `/apply` and Ashby `/application` match their Job pages. On `www.okta.com`, `/company/careers/opportunity/<id>?gh_jid=<id>` also matches `/company/careers/rd/<slug>-<id>` when the full IDs agree. Other query identifiers remain significant. Unknown redirects, embedded form URLs that differ from the parent page, and ambiguous matches need a manual pick: filter/select the intended Job from the picker. **Refresh Jobs** retries detection.

The `tabs` permission lets detection read page URLs when switching tabs or reopening the panel; static content-script matches alone do not provide that metadata. It does not grant permission to inject on other sites. The status line distinguishes a detected Job, no stored match, and an auto-detection error (including an unavailable URL or failed server request). The manual picker stays available after a detection error. A detected Job is shown in the picker even when it is outside the normal Jobs query.

On other sites, right-click the page or a field and choose **Fill with Joule**, or press **Ctrl+Shift+Y** (**Command+Shift+Y** on macOS). This injects the same worker using temporary `activeTab` access and opens the side panel; select the intended Job and click **Fill**. Change the shortcut at `chrome://extensions/shortcuts` if it conflicts. Upwork, LinkedIn, Indeed and Glassdoor, including subdomains, are refused.

Fill handles required fields and optional identity fields with saved values in `cv.yaml` (including LinkedIn, GitHub, and website/portfolio). Optional free-text questions, optional comboboxes, surveys, demographics, and consent remain manual. Resume upload is an explicit override through **Attach resume**. Cover Letters are skipped. Fill replays exact normalized question matches from `profile/answers.yaml`, mapping saved option labels to select/radio values. For unmatched questions, click **Ask** beside the field; answers come from your Profile and appear only in empty fields. Review and edit the result, then click **Save to bank** to save the field's current answer (the option label for selects/radios). Save to bank is offered only on rows marked `ask`, including after a successful Ask or a manual answer. Rows marked `set` have no action buttons; a successful Ask removes its Ask button and keeps Save to bank for your final edits. Next Fill replays the saved answer; saves are refused when the bank already exceeds 200 KB. Sensitive questions stay manual, including when saved in the bank. An unanswerable option question stays empty. Ask alone does not save answers. Save reads the current answer using the field’s stable identity, so an input replacement or changed option cache does not discard a manual answer. Fragment-only URL changes preserve pending rows; auto-detection changing the active Job does not cancel a bank save, since the bank is shared across Jobs. A missing, ambiguous, or changed question is refused with a specific reason.

The sidepanel **Ask a question** box answers operator-typed questions using the selected Job and the same Profile/answer-bank context as field Ask. It needs no page field. Review the answer and click **Copy answer** to paste it where needed. Select a Job manually if the page is unmatched.

Required react-select comboboxes now support bank replay and **Ask**. Fill opens required empty menus to discover choices; searchable menus also support exact option lookup after a Profile answer. Optional comboboxes and surveys stay untouched. Existing selections and operator text are preserved. Unsupported markup, slow menus (over 1.5 seconds), and non-exact or ambiguous answers stay manual. Real react-select behavior still requires the operator’s live trial.

Use **Attach resume** for the latest Tailored CV, or **Generate and attach resume** if none exists. Static scripts run in matching ATS frames, including employer-hosted embeds. Unknown-site injection targets the main frame; if an embed cannot be reached, open its URL directly and use the context menu or command there. For phone widgets, store an international number (including `+1` for the US) in `cv.yaml` → `basics.phone`. Location facts belong in `basics.location`. Exact form answers (including the complete country/city option labels) can be saved in `answers.yaml`; keep work authorization and sponsorship facts there too so Ask can use them.

Ashby required Yes/No groups are driven through their exact choice buttons, with submit defaults cancelled and existing answers preserved. Location typeaheads use the surrounding question label and required marker; put the full option label in `cv.yaml` → `basics.location.label` (for example, `Denver, Colorado, United States`). Plain city and state/province questions use `basics.location.city` and `region`; both must be present. Postal code, salary, work authorization and sponsorship questions need an exact bank answer or manual Ask. Ashby name/email and other basic text inputs receive focus, input/change, and blur so their controlled state commits immediately. This behavior was checked on a public Ashby form in headless Chromium; the operator’s specific posting still needs a trial.

Lever custom questions show their full question text and radio choices. Required current-location fields select an exact search result: for US locations, Fill uses `basics.location.city`, `region` (state abbreviation), and `countryCode: US` to match labels such as `Denver, CO, USA`; otherwise it uses `basics.location.label`. Pronoun controls stay untouched and are omitted from the field list.

Actual Chrome permissions, cross-origin frames, React widgets and real ATS behavior still need the operator's manual trial (design §5).

Run the focused checks with `npm ci && npm test` in this directory. JS intentionally has no build step (design D14). `test/fixtures` contains small reconstructions of the markup verified in the design record, rather than full fetched pages. jsdom's missing layout is stubbed in tests; the production visibility checks use real rectangles.

Every **Fill** now records a diagnostic trace automatically through the configured joule server. Restart the server, reload the unpacked extension, and reload any already-open forms after updating. No export or extra click is needed. Files are written to `~/.joule/traces/<UTC timestamp>-<unique id>.json` on the **server host** (`JOULE_DATA_DIR/traces` if configured); a coding agent on that host can read the latest file. The panel reports a failed trace save. Traces are local files only, with directory mode `0700` and file mode `0600`; they accumulate until you delete them.

Each version-1 JSON trace contains the page route, Job id (null for URL-only replay), recording time, frame/field references, CSS selector, question label, detected DOM type/role, attempted action, outcome, errors, and before/after **presence booleans** (null when a frame is unavailable). It contains no field values, answer text, option lists, HTML, screenshots or raw exception/validation messages. URL credentials, query strings and fragments are removed; page routes, selectors and labels remain diagnostic metadata, so use this on public application forms. The numeric frame reference identifies embedded fields. Failed Fill attempts also try to save a trace with a `fill-failed` category; a disconnected server cannot save a trace.

After writing, Fill commits touched inputs with blur and waits 750 ms for common framework/debounce updates. It reads native `validity.valueMissing`, `aria-invalid`, visible linked/nearby required-error categories, empty required controls, lost values and detached controls. A widget counts as present only when its selection is committed. These signals are observations, not proof of acceptance: `aria-invalid` can mean an invalid format rather than missing data, inaccessible framework state and validators that run only on submit remain unknown, and later async errors can fall outside the observation window. Fill never calls validation methods, submits, or marks a Job applied. Ask and Attach retain their existing behavior and do not create Fill traces.

An agent can reproduce a public form from its URL, using the same extension worker and Profile/answer-bank matching, without adding a Job:

```sh
cd extension
npm ci
npx playwright install chromium
npm run replay -- 'https://employer.example/apply'  # default joule: http://localhost:8000
npm run replay -- 'https://employer.example/apply' 'http://localhost:8000' --headed
npm run test:replay  # real Chromium + local form + temporary joule server smoke test
```

The runner prints `N filled; validation: clicked; trace: /.../traces/....json`. It uses Playwright's bundled Chromium, an unpacked temporary copy of the extension, and a fresh disposable browser profile; it does not reuse login sessions. Only that copy receives broad HTTP(S) access to reach employer embeds; the installed extension's permissions are unchanged. After Fill, the runner blocks every browser HTTP(S) request and puts the browser offline before clicking one unambiguous visible, enabled **Submit**, **Submit application**, **Send application**, or **Apply** button. Page Service Workers are disabled and WebSockets are closed from startup so they cannot bypass request routing. The page’s own click/submit handlers and native validation run; no application request can reach the employer. The final trace is sent to the configured local joule endpoint by the Node process outside the offline browser. This Submit pass exists only in the replay runner; the installed extension still never submits. It does not call Ask, generate/attach Drafts, or change Jobs. A public form must load without login or human challenges; expired postings, CAPTCHA, inaccessible frames and unsupported widgets can still prevent reproduction. For `test:replay`, install the repo's Python dependencies with `uv sync` first.

Replay traces add `validation: {status, network_blocked: true, blocked_requests}` and per-field `submit-native-value-missing`, `submit-native-invalid`, `submit-aria-invalid`, `submit-required-error`, `submit-validation-error`, or `submit-field-unavailable` signals. The original Fill signals remain separate. `clicked` means the runner attempted the page’s Submit control with the browser offline; it does not mean an application was sent. No button, multiple candidate buttons, or a click failure produces `no-submit-control`, `ambiguous-submit-control`, or `submit-click-failed` instead of a claimed validation result. The runner waits one second after clicking, then categorises the page’s reflected validation state without saving error text or answers. Native navigation may replace the document with an offline error page, recorded as unavailable fields. Server-side validation cannot run offline; missing lazy-loaded validators, late asynchronous updates and errors caused by the blocked network remain limitations.
